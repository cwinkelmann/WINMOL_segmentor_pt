Section 1

The test set decides what you can see

The same eleven models were trained twice: once on the original SpecDS tiles and scored on TestDS, once on fixed-metre tiles and scored on a held-out orthomosaic (Campus Oberheide). The model set is identical. The conclusions are not.

SpecDS → TestDS 117 tiles · spread 2.7 pts · recall 0.73–0.79
Fixed-metre → held-out orthomosaic 900 tiles · spread 10.4 pts · recall 0.49–0.65
F1 0.600.650.700.750.78

On TestDS the eleven models span 2.7 points and the plain UNet ranks fifth. On a real held-out site the same models span 10.4 points and UNet ranks last but one. Recall tells the same story: 0.73–0.79 on TestDS against 0.49–0.65 on unseen ground.

TestDS is very likely not a site holdout. It and SpecDS were produced by the same R script run on Quesenbank, and neither carries tile provenance, so the closest centre-to-centre distance between them cannot be computed. A test set on which UNet ties HRNet and recall reaches 0.79 is measuring in-domain performance.

The practical consequence: any architecture or preprocessing decision made against TestDS would have looked like a tie. That is not a criticism of the original choice — it is what happens when the test set shares ground with training.

Extraction is the largest lever

Three tile-extraction methods, three architectures, all sharing one validation and one test set so only the training data differs.

 Test F1 on Campus Oberheide, 900 tiles, all from scratch. Fixed-metre wins every cell — the one unqualified result in the study.

Quote the gain as a range, not a number: +26.5 on UNet, +15.3 on HRNet, +8.7 on SegFormer. All positive and all large, but UNet is the outlier rather than the headline — it is the weakest model here and takes the most damage from weak data.

The R port's deficit is specifically recall (0.24–0.43 at precision 0.85–0.88). Its acceptance rule sums the whole area of every polygon intersecting the footprint rather than the part inside it, so tiles qualify on stems that mostly fall outside. The model is trained on ground emptier than its labels imply, and learns to withhold.

Validation ranks these models in nearly the reverse order of test. SegFormer mit_b5 posts the highest validation F1 in the entire study (0.7731) and places fourth on test. HRNet+ImageNet beats HRNet-from-scratch on validation and loses on test.

Capacity and pretrained weights buy in-domain fit that does not survive the site change — so a model selected on this corpus's validation split is the wrong model for the Analyzer.

Plain supervised ImageNet beats both self-supervised regimes — by 7.0 points over DINOv3 and 10.1 over FCMAE. Self-supervised features learned from 1.7 billion web images transfer worse here than ordinary label-supervised ones, and the gap is entirely recall (0.610 vs 0.530 vs 0.486 at near-identical precision).

The synthetic figures replace an earlier, wrong set. The first pass reported Blender at +1.1 and SD+UNet at +3.6. Those runs are void: run_two_stage built stage 2's loaders without passing --val-data-dir, silently falling back to a random split of the training tiles — a different signal from the single-stage baselines it was compared against, and a leaky one, since the samplers oversample and adjacent tiles overlap.

Test metrics were never affected. Checkpoint selection was, and it moved results by up to 3.9 points and flipped the sign on two of three arms. Fixed in a1ca11d, pinned by a regression test.

Section 5

Anti-aliasing: not the Analyzer's problem

The Analyzer resamples two different ways. utils/Prediction.py::_resize_batch calls skimage with anti_aliasing=False; its stream path uses Resampling.cubic, which filters. They disagree on every downsampled tile. Two models were trained on identical footprints differing only in that filter, then each scored on both test sets.

The mismatch costs nothing — ≤0.05 F1 in both directions. Which filter you train with is worth +1.0 in favour of no anti-aliasing; which filter you infer with is worth 0.05, which is noise.

So the resize-path disagreement is not the source of the Analyzer's inconsistent behaviour. tile_size remains the prime suspect: ExecutionPlan.py:95-97 makes effective ground resolution tile_size / 512, and a fixed-scale model loses 5.2 F1 across ±30% zoom.

Why spruce, not beech. Anti-aliasing only acts when a tile is downsampled, and at the Analyzer's default 2.93 cm/px the beech orthomosaics are too coarse — Campus upsamples ×0.46, Oberheide ×0.87. A beech 2×2 would have measured nothing. The Barnekow spruce sites are 1.58–1.76 cm/px, so every split here downsamples ×1.67–1.85.

Section 6

What this does not establish

  • Every run is n = 1. Differences under roughly one point are directional only. lr and seed are not yet configurable, which blocks replicates.
  • One site fold, not four. The extraction verdict is paired across three architectures, which controls for model choice but not for site — and site identity has outweighed architecture, pretraining and preprocessing in every comparison run here.
  • The AA result sits on 447 training tiles of spruce, against 2,700 of beech for the main study. The paired construction makes the filter comparison valid; the absolute F1 is not comparable to 0.7229.
  • PAN is untested, not refuted. Its evaluation explodes while training stays stable — a BatchNorm-over-1×1 hazard this repo has hit before. Diagnosing it needs the same config mechanism the replicates need.
  • TestDS cannot be verified as a holdout, so Section 1's contrast is the strongest available reading, not a proof.
